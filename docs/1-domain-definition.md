## 1. 비즈니스 개요
- **해결하려는 문제**: 식자재를 구매하는 외식업체·급식업체 등 B2B 거래처가 진행 중인 프로모션 정보를 영업 담당자 개별 안내, 전화, 카톡 등 흩어진 채널로만 접해 놓치기 쉽고, 참여 의사를 남길 공식적인 수단이 없다. 관리자 입장에서도 프로모션을 등록·관리하고 거래처의 참여 반응을 확인할 창구가 없다.
- **대상 사용자**:
  - 거래처 담당자: 외식업체·급식업체 등 B2B 거래처 소속으로, 현장(스마트폰)에서 진행 중인 프로모션을 확인하고 참여 신청하는 사용자
  - 관리자: 식자재 유통사 소속으로, 사무실(데스크탑)에서 프로모션을 등록·관리하고 참여 현황을 확인하는 사용자

## 2. 핵심 엔티티 및 용어
| 용어 | 정의 | 비고 |
|---|---|---|
| 사용자(User) | 로그인하여 앱을 이용하는 계정. 역할(거래처 담당자/관리자)을 가짐 | 회원가입은 거래처 담당자만 해당 |
| 거래처(Partner) | 프로모션에 참여하는 B2B 고객사(외식업체, 급식업체 등) | 거래처 담당자 계정과 1:1 매핑으로 단순화 |
| 프로모션(Promotion) | 관리자가 등록하는 판촉 활동. 유형: 가격 할인 / 샘플 증정 / 신제품 시식 / 1+1 | 게시/종료 상태를 가짐 |
| 쿠폰 이벤트(CouponEvent) | 프로모션에 선택적으로 부착되는 "랜덤 쿠폰 뽑기" 부가 이벤트 | 선착순 50명 한정 |
| 참여신청(Application) | 거래처 담당자가 특정 프로모션에 남기는 참여 의사 기록 | (프로모션, 거래처) 조합당 1건만 존재 |
| 추첨결과(DrawResult) | 쿠폰 이벤트 참여신청 시 즉시 확정되는 할인율 당첨 결과(5%/10%/15%/20%) | 참여신청 1건당 최대 1건, 재추첨 없음 |

## 2-1. 엔티티 속성(필드)
| 엔티티 | 필드 | 설명 |
|---|---|---|
| User | id, email, password_hash, role(거래처담당자/관리자), name, phone, created_at, updated_at | 로그인 계정 |
| Partner | id, name(거래처명), user_id(FK, 1:1), created_at | 거래처 담당자 계정과 1:1 매핑 |
| Promotion | id, title, type(가격할인/샘플증정/신제품시식/1+1), description, status(임시저장/게시됨/종료됨), created_by, created_at, updated_at | |
| CouponEvent | id, promotion_id(FK, 1:1), capacity(정원, 고정값 50), applied_count(누적 신청 수), created_at | applied_count는 취소 시에도 감소하지 않음(슬롯 미반환). applied_count >= capacity면 마감 |
| Application | id, promotion_id(FK), partner_id(FK), status(신청됨/취소됨), applied_at, canceled_at(nullable) | (promotion_id, partner_id) 조합 유니크 제약. 프로모션 종료 후에도 취소 가능 |
| DrawResult | id, application_id(FK, 1:1), discount_rate(5/10/15/20 중 1), confirmed_at, expires_at(confirmed_at + 1개월) | 재신청 시 동일 application_id 레코드를 덮어씀(upsert). 이전 값은 폐기, 별도 무효화 상태 필드 없음 |

## 3. 엔티티 간 관계
- 거래처(1) - 사용자(1): 거래처 담당자 계정 1개는 거래처 1곳에 대응
- 관리자(1) - 프로모션(N): 관리자가 여러 프로모션을 등록·관리
- 프로모션(1) - 쿠폰이벤트(0..1): 프로모션에 쿠폰 이벤트는 선택적으로 1개만 부착
- 프로모션(1) - 참여신청(N): 하나의 프로모션에 여러 거래처가 참여신청 가능
- 거래처(1) - 참여신청(N): 한 거래처는 여러 프로모션에 각각 참여신청 가능 (단, 동일 프로모션에는 1건)
- 참여신청(1) - 추첨결과(0..1): 쿠폰 이벤트가 있는 프로모션에 참여신청한 경우에만 추첨결과가 생성됨

## 4. 액터(역할)
| 역할 | 설명 |
|---|---|
| 거래처 담당자 | 회원가입/로그인 후 프로모션 목록·상세 조회, 참여 신청/취소, 내 신청 목록(당첨 결과 포함) 조회, 마이페이지 관리 |
| 관리자 | 프로모션 등록·수정·게시/종료 관리, 쿠폰 이벤트 설정, 참여 현황 확인, 마이페이지 관리 |

## 5. 비즈니스 규칙 / 제약
- BR-1. 모든 기능은 로그인 후에만 이용 가능하다 (비로그인 접근 불가). (→ EX-5)
- BR-2. 거래처 담당자는 회원가입 절차를 거쳐야 로그인이 가능하다. 관리자 계정 생성은 MVP 범위 밖(사전 시딩 또는 수동 생성)으로 한다.
- BR-3. 참여신청은 (프로모션, 거래처) 조합당 유일해야 한다. 취소·재신청은 새 레코드를 생성하지 않고, 기존 참여신청 레코드의 상태를 전환하는 방식으로 처리한다. (신청됨 → 취소됨 → 재신청 시 다시 신청됨) (→ UC-3, UC-5, EX-2)
- BR-4. 쿠폰 이벤트가 붙은 프로모션에 참여신청하면, 서버가 아래 확률분포에 따라 즉시 할인율을 추첨하여 결과를 확정하고 화면에 보여준다. (→ UC-4)

  | 할인율 | 당첨 확률 |
  |---|---|
  | 5% | 40% |
  | 10% | 30% |
  | 15% | 20% |
  | 20% | 10% |

- BR-5. 쿠폰 이벤트 추첨 결과는 재추첨을 허용하지 않는다. 참여신청을 취소했다가 재신청하는 경우, 새로 추첨된 DrawResult가 동일 application_id의 기존 레코드를 덮어쓰며(upsert) 이전 값은 폐기된다. 재신청 시점에 선착순 50명 마감 여부를 다시 확인해 새로 추첨한다(마감 시 신청 자체가 거부됨). (→ UC-4, EX-4)
- BR-6. 쿠폰 이벤트는 선착순 신청자 50명까지만 적용된다(CouponEvent.capacity = 50). 신청이 성공할 때마다 CouponEvent.applied_count를 1 증가시키며, **참여신청 취소 시에도 applied_count는 감소하지 않는다(슬롯 미반환)**. 즉 누적 신청 성공 건수가 50건에 도달하면 이후의 모든 신청 시도는 신규 신청이든 취소자의 재신청이든 동일하게 "마감됨" 안내와 함께 거부된다(대기열 없음, 취소로 인한 자리 재개방 없음). (→ EX-1, EX-4)
- BR-7. 동시에 여러 신청이 몰리더라도 applied_count 증가와 마감 여부 판정은 원자적으로 처리되어, 정확히 50건까지만 성공하고 51번째부터는 거부된다.
- BR-8. 당첨된 할인율은 확정일로부터 1개월 이내에만 사용 가능하다고 안내한다(실제 사용 처리/검증 로직은 MVP 범위 밖).
- BR-9. 프로모션은 관리자가 게시 상태(status=게시됨)로 전환해야 거래처 담당자의 "진행 중인 프로모션 목록"에 노출된다. 즉 문서 전반에서 "진행 중인 프로모션"은 status=게시됨 상태의 프로모션을 가리키는 동일한 용어다.
- BR-10. 종료된 프로모션(status=종료됨)은 거래처 담당자의 "진행 중인 프로모션 목록"에서는 제외되지만, 해당 프로모션에 이미 참여신청한 거래처의 "내 신청 목록"에서는 종료 후에도 계속 조회 가능하다(신청 이력 보존).
- BR-11. 종료된 프로모션에는 신규 참여신청은 할 수 없지만, 이미 존재하는 참여신청은 종료 이후에도 취소할 수 있다. (→ UC-5, EX-3)

## 6. 상태(생명주기)
- 프로모션(Promotion): 임시저장(작성중) → 게시됨 → 종료됨
- 참여신청(Application): 신청됨 → 취소됨 → (재신청 시) 신청됨
- 추첨결과(DrawResult): 확정됨 (생성 즉시 확정, 별도 상태 전이 없음)
- 쿠폰이벤트(CouponEvent): 모집중(applied_count < 50) → 마감됨(applied_count = 50, 이후 되돌아가지 않음)

## 유스케이스
- UC-1. 거래처 담당자 회원가입 및 로그인
- UC-2. 거래처 담당자: 진행 중인 프로모션 목록/상세 조회
- UC-3. 거래처 담당자: 프로모션 참여 신청
- UC-4. 거래처 담당자: 쿠폰 이벤트 참여 시 즉시 추첨 결과 확인
- UC-5. 거래처 담당자: 내 참여신청 목록(당첨 결과 포함) 조회 및 신청 취소(종료된 프로모션의 기신청 건 포함)
- UC-6. 관리자: 프로모션 임시저장(작성 중)/등록·수정
- UC-7. 관리자: 프로모션 게시·종료 처리(쿠폰 이벤트 설정 포함)
- UC-8. 관리자: 프로모션별 참여 현황 확인
- UC-9. 공통: 마이페이지에서 내 정보 조회/수정, 비밀번호 변경

## 예외 케이스
- EX-1. 쿠폰 이벤트 선착순 50명 마감 후 신청 시도 → 신청 거부, "마감되었습니다" 안내 (→ BR-6)
- EX-2. 이미 신청한 프로모션에 중복 신청 시도 → 신규 레코드 생성 대신 기존 레코드 상태 확인 후 거부 또는 안내 (→ BR-3)
- EX-3. 종료된 프로모션에 대한 신규 참여 신청 시도 → 신청 불가 안내 (단, 기존 참여신청 취소는 허용) (→ BR-11)
- EX-4. 취소된 신청을 재신청할 때 쿠폰 이벤트가 이미 마감된 경우 → 재신청 거부, "마감되었습니다" 안내 (→ BR-5, BR-6)
- EX-5. 로그인하지 않은 상태로 기능 접근 시도 → 로그인 페이지로 이동 (→ BR-1)

## MVP 범위 (포함/제외)
- **포함**: 회원가입/로그인, 프로모션 등록·조회·게시/종료 관리, 참여 신청/취소(상태 전환 방식), 랜덤 쿠폰 뽑기 즉시 추첨(재추첨 불가, 선착순 50명), 마이페이지(정보 수정/비밀번호 변경), 반응형(모바일/데스크탑) UI
- **제외**: 실제 주문/결제/정산, 재고 실시간 연동, 승인 워크플로우, 거래처 등급별 차등가, 포인트 적립, 검색 기능, 경품(쿠폰) 재고 관리
